# IP-005 (DRAFT): Canonical Agreement Package

## Status

Experimental proof profile. This proposal does not change the accepted template schema or declare the EVM profile canonical.

## Problem

The current EVM SDK hashes `JSON.stringify(agreement)` while accepting initialization values separately. Object key order can therefore change the document hash, initialization is not covered by that hash, and unsupported execution semantics can be silently reduced during compilation.

An agreement cannot make a strong “what was authored is what executes” claim unless all parties can reproduce one digest over the same semantic package and the compiler fails closed whenever the selected runtime cannot represent part of it.

## Proposed package

The experimental package envelope contains:

- `schemaVersion` — the envelope version;
- `profile` — the executable profile and compiler version whose semantics are selected;
- `target.chainId` — the runtime chain the executable references target;
- `agreement` — prose, variables, contracts, and execution policy;
- `initialization.values` — the values supplied when the agreement instance is created.

The envelope schema is [`schemas/agreement-package.schema.json`](../schemas/agreement-package.schema.json). The positive golden vector is [`test-vectors/canonical-package-v0/reference-package.json`](../test-vectors/canonical-package-v0/reference-package.json).

`uint256` initialization values use base-10 strings so the package remains JSON and does not lose integer precision. Addresses, text, dates, and bytes values are strings; booleans are JSON booleans.

## Canonicalization and digest

The package is canonicalized recursively using the JSON Canonicalization Scheme shape:

1. Object properties are sorted in ECMAScript UTF-16 code-unit order.
2. Array order is preserved.
3. Strings, booleans, nulls, and finite JSON numbers use ECMAScript `JSON.stringify` serialization.
4. `undefined`, functions, symbols, bigint values, non-finite numbers, sparse arrays, and cyclic values are rejected.
5. The resulting JSON text is UTF-8 encoded.
6. `packageDigest = keccak256(canonical UTF-8 bytes)`.

For the strict EVM profile, the on-chain `docHash` is the `packageDigest`. The selected profile and compiler version are inside the canonical package and therefore inside that digest. The creation permit separately continues to bind the document URI and compiled initialization arrays.

## Fail-closed compilation

The strict compiler must return a machine-readable report and refuse compilation when the EVM profile would otherwise drop semantics. The first proof profile rejects at least:

- zero or multiple trigger conditions on a transition;
- an unsupported executable profile, profile version, or compiler version;
- transition condition types other than `isValid`;
- transition references to unknown inputs;
- `revertOnFailure: false`, because the current engine always reverts on action failure;
- action hooks without a matching transition;
- referenced action contracts whose declared `chainId` differs from `target.chainId`;
- on-chain variable validations that the current EVM compiler cannot enforce, including `pattern` and `step`.

The legacy compiler remains available during the experiment. This proposal defines an additive strict path so existing agreements are not silently reinterpreted.

## Proof obligation

The profile is useful only when an independent implementation can:

1. reproduce the canonical JSON and digest from the source package;
2. obtain an empty loss report for the positive vector;
3. observe deterministic failures for the negative vectors;
4. verify that the compiled `docHash` equals the package digest; and
5. show that changing prose, execution policy, initialization, or target chain changes the digest.

## Non-goals

- Selecting this package as the final cross-runtime Agreements Protocol representation.
- Generalizing commitments, disputes, remedies, or settlement into first-class modules.
- Changing deployed agreement clones.
- Defining legal enforceability or production security requirements.
