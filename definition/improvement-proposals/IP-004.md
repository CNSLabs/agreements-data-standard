## Overview

### Problem Statement

1. Poor variable interoperability between the protocol logic and a ui input client / AI Agent
  * no clear separation of input variables and protocol IO layer
  * lack of variable decorators to improve verbosity across the stack
  * poorly defined validation rules for use across the stack
  * overly nested variable creating additional complexity
2. Content limitation to MDAST
  * Should support more than one type
3. Lack of descriptors for describing the template and it's use
4. No JSON Schema for the agreement protool
  * Validation tools
  * LLM inexplicit context

### Proposed Solution

1. Create a flat variable structure supporting descriptors and validation requirments for the protocol IO layer and the content/UI layer.
2. Add support for multiple content types ('mdast', 'md')
  * Incrementally add support for types e.g. 'blocknote', 'mdx', 'html'
  * Provide tooling to support variable and custom types across content types
3. Add additional metadata descriptors to the agreement
4. Add JSON scheama definitions for mdast and agreement template.
